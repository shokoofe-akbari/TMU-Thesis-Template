# راهنمای انتشار نسخه جدید

## کنترل پیش از انتشار

1. شماره نسخه در `VERSION` و `CITATION.cff` یکسان باشد.
2. تغییرات در `CHANGELOG.md` ثبت شده باشند.
3. قالب ارشد و دکتری در حالت `bib` با `build.ps1` بدون هشدار ساخته شوند.
4. حالت `manual` نیز برای هر دو مقطع آزمون شود.
5. فایل‌های PDF پیش‌نمایش با آخرین منبع همسان باشند.
6. فونت‌ها با مجوزهای ثبت‌شده در `THIRD_PARTY_NOTICES.md` تطبیق داده شوند.
7. هیچ اطلاعات شخصی واقعی در `Attributes` یا PDF نمونه باقی نمانده باشد.

## ساخت بسته‌ها به‌صورت محلی

پس از ثبت commit:

```powershell
.\scripts\package-release.ps1 -Version v1.0.0
```

خروجی‌ها در پوشه `dist` ساخته می‌شوند:

```text
TMU-Thesis-MSc.zip
TMU-Thesis-PhD.zip
SHA256SUMS.txt
```

پوشه `dist` وارد Git نمی‌شود.

## انتشار خودکار

با push شدن tag مطابق الگوی `v*`، گردش کار `release.yml` اجرا می‌شود:

```powershell
git tag -a v1.0.0 -m "TMU Thesis Template v1.0.0"
git push origin v1.0.0
```

این گردش کار Release را ایجاد و دو ZIP مستقل و فایل checksum را به آن پیوست می‌کند.

## سیاست شماره نسخه

- `MAJOR`: تغییر ناسازگار در ساختار یا روش استفاده؛
- `MINOR`: قابلیت جدید سازگار با نسخه قبل؛
- `PATCH`: رفع خطا، اصلاح متن یا بهبود مستندات.
