# ساختار مخزن

## پوشه‌های مقطع

پوشه‌های `MSc` و `PhD` کاملاً مستقل‌اند و ساختار مشترک زیر را دارند:

| مسیر | کاربرد |
|---|---|
| `Attributes/` | صفحات عنوان، مشخصات، تأییدیه‌ها، تقدیم و سپاس |
| `Conductors/` | منابع، واژه‌نامه‌ها و اجزای انتهایی |
| `Contents/` | چکیده‌ها، پیش‌گفتار، فصل‌ها و پیوست |
| `Figures/` | تصاویر رسمی و شکل‌های نمونه |
| `Fonts/` | فونت‌های محلی و قابل‌بازتوزیع |
| `Submission/` | فایل Word چهارصفحه‌ای ویژه تحویل پایان‌نامه‌های ریاضی |
| `*.cls` | تعریف ساختار و صفحات قالب |
| فایل اصلی `*.tex` | نقطه آغاز پردازش پایان‌نامه |
| `build.ps1` و `build.cmd` | ساخت و کنترل کیفیت محلی |
| `UPDATE.md` | سابقه و دامنه ویرایش فنی |

## پوشه docs

- `getting-started.md`: نصب و شروع محلی یا Overleaf؛
- `bibliography.md`: دو شیوه منابع؛
- `troubleshooting.md`: خطاهای رایج؛
- `repository-structure.md`: نقشه فایل‌ها؛
- `releasing.md`: فرایند انتشار نسخه جدید؛
- `official-format-1403.md`: ترتیب صفحات، الزامات چکیده، تأییدیه PDF و Word چهارصفحه‌ای؛
- `screenshots/`: پیش‌نمایش صفحات خروجی.

## پوشه licenses

متن مجوز فونت‌های همراه قالب در این پوشه نگهداری می‌شود. نگاشت هر فونت به مجوز آن در `THIRD_PARTY_NOTICES.md` آمده است.

## پوشه scripts

اسکریپت `package-release.ps1` از وضعیت ثبت‌شده Git دو بسته مستقل ZIP و فایل SHA-256 می‌سازد. اسکریپت `build-math-submission-docx.py` نیز دو همراه Word چهارصفحه‌ای را بازتولید می‌کند.

## پوشه .github

- گردش کار `latex.yml` چهار حالت ساخت را بررسی می‌کند؛
- گردش کار `release.yml` با ثبت tag، بسته‌های مستقل را منتشر می‌کند؛
- فرم‌های Issue اطلاعات لازم برای بازتولید خطا را دریافت می‌کنند.
